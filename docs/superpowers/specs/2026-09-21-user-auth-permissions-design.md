# 工具包账号登录、角色权限与版本署名设计

日期：2026-09-21

状态：待用户审阅；尚未实施

## 1. 目标与已确认需求

在运维工具箱中增加账号密码登录、用户白名单和三种角色：`admin`、`operate`、`readonly`。管理员管理用户及角色，操作员维护配置和版本，只读用户查询和查看。版本归档记录编辑者、提交者的用户名及相应时间。

用户已选择新增账号密码登录服务。本设计将账号白名单解释为管理员创建且处于启用状态的账号集合，不开放自行注册。角色作用于整个工具箱工作空间；本期不增加项目级授权。

下文中的管理权限继承、导出限制、自动归档署名和旧数据迁移规则是具体实施建议，随本文一起审阅。

## 2. 当前工程与方案选择

当前 `Tools/ops-toolkit` 为浏览器单文件工具。`src/store.js` 使用 IndexedDB 存储配置、草稿和版本，`src/app.js` 在浏览器发起修改和自动归档。`serve.mjs` 只提供静态页面。当前版本的 `createdAt` 来自浏览器，没有用户字段。

采用同源 Node.js 业务服务与 SQLite 持久化：页面与 API 从同一服务提供，账号、会话、共享配置和版本保存在服务端。沿用现有转换、证书解析和配置校验模块，以明确的业务命令替换浏览器直接修改完整工作空间的流程。

与独立认证服务加独立数据库相比，该方案适合当前单个工具箱，部署组件较少；以后需要多实例部署时再迁移数据库。纯浏览器账号隔离无法可靠执行访问控制，无法满足本次权限目标。

## 3. 权限矩阵

| 操作 | admin | operate | readonly |
| --- | --- | --- | --- |
| 查看配置、筛选搜索、查看草稿及版本差异 | 允许 | 允许 | 允许 |
| 新增、编辑、复制、归档、恢复、删除配置 | 允许 | 允许 | 禁止 |
| 保存草稿、手动归档、恢复版本、清理旧版本 | 允许 | 允许 | 禁止 |
| 完整备份和脱敏导出、配置及版本下载 | 允许 | 允许 | 禁止 |
| 校验并导入备份 | 允许 | 允许 | 禁止 |
| 修改自动归档等共享业务设置 | 允许 | 允许 | 禁止 |
| 创建用户、启停白名单、分配角色、重置密码 | 允许 | 禁止 | 禁止 |
| 修改自己的密码、退出登录、调整本机主题 | 允许 | 允许 | 允许 |

`admin` 继承 `operate` 的业务权限。所有受保护 API 先认证再授权，角色不由请求体指定。未登录返回 401，无权限返回 403；界面同时隐藏或禁用不允许的入口。

只读页面不启动草稿保存、自动归档或任何共享数据写入。切换主题等个人显示偏好独立保存在本机，不产生业务写入。只读账号可使用本地转换和证书解析进行临时查看，但不能将结果保存为配置或使用导出入口。禁止导出是产品操作限制，不能阻止用户手动复制已经获准查看的信息。

本期三个角色均可查看工作空间内相同的配置内容，继续沿用现有敏感字段遮罩和显式显示行为；角色不承担字段保密分级。

## 4. 账号、密码与会话

- 管理员创建唯一用户名、初始密码和角色；启用即加入白名单，禁用即移出白名单。用户名创建后不可修改，也不可复用；用户使用禁用而非物理删除，保证历史关联稳定。
- 首个管理员通过仅在服务器执行的一次性初始化命令创建。命令仅在尚无账号时可用，不提供公开初始化接口、不内置默认密码，不在命令行参数或日志中输出密码。
- 密码使用带独立随机盐的抗暴力破解密码哈希存储，不存明文。支持本人改密与管理员重置；初始及重置密码要求首次登录修改，完成前仅允许改密和退出。
- 服务端生成不可预测的会话令牌，仅在数据库存其摘要；通过 HttpOnly、SameSite Cookie 传递，HTTPS 部署启用 Secure。生产环境以 HTTPS 部署，本机开发允许回环 HTTP。
- 会话绝对有效期为 8 小时，退出即撤销。改密、重置密码、禁用或角色变更撤销该用户全部旧会话；每次请求重新验证账号状态与当前角色。
- 登录失败使用统一提示，不暴露用户名是否存在；以账号和来源地址共同限速。写请求检查同源来源及会话绑定的 CSRF 令牌。
- 不允许禁用或降级最后一个启用的管理员，检查和更新在同一事务完成。

用户管理页面仅对管理员可见，提供用户列表、用户名搜索、角色和状态筛选、新建、角色调整、启停及重置密码。账号及会话数据不进入普通配置备份。

## 5. 编辑与提交记录

### 字段含义

| 记录 | 字段 | 含义 |
| --- | --- | --- |
| 当前草稿 | `editedByUserId`、`editedByUsername`、`editedAt` | 最近一次成功保存草稿的用户 ID、用户名快照和服务端时间 |
| 归档版本 | `editedByUserId`、`editedByUsername`、`editedAt` | 本版本所取草稿的最后编辑信息快照 |
| 归档版本 | `submittedByUserId`、`submittedByUsername`、`submittedAt` | 创建该版本的提交者和服务端提交时间 |
| 归档版本 | `source` | 首次保存、手动提交、自动归档或历史恢复 |
| 导入记录 | `importedByUserId`、`importedByUsername`、`importedAt` | 本次导入的操作者和服务端时间，与历史作者分开 |

编辑者指最后一次成功保存该草稿的用户，不表示所有参与编辑的人；本期不增加逐次编辑事件列表。元数据修改在配置记录保存修改人和修改时间，不冒充内容草稿的编辑者。

用户 ID 用于关联，用户名快照用于稳定展示。禁用账号、修改角色或重置密码不会改变已有历史署名。新产生的时间统一为服务端 UTC，页面以浏览器本地时区显示到秒并标注时区。`createdAt` 保留为兼容字段，新版本与 `submittedAt` 相等。

### 各类归档规则

1. 首次保存：草稿编辑者和版本提交者都是当前登录用户，时间在服务端事务中生成。
2. 手动提交：编辑者从已保存草稿复制，提交者取当前登录用户；例如 A 编辑、B 提交，显示 A 与 B 各自的时间。
3. 自动归档：由服务端检查草稿的有效性、闲置至少 2 秒以及距上次归档至少 60 秒；使用最近编辑者作为关联提交用户，`source=auto`，界面明确显示“自动归档（关联用户：用户名）”。提交时间为实际归档时间，编辑时间保持草稿时间。
4. 自动归档前重新检查最近编辑者仍启用且具有写权限；禁用或降为只读后暂停其待归档草稿的自动归档，允许有权限的用户手动接手提交。后端调度不依赖只读用户打开页面。
5. 恢复历史版本：保留旧版本记录，以当前操作者创建新草稿和新版本，记录新的编辑／提交身份与时间，保留恢复来源；按现有逻辑保留被替换的未归档草稿。
6. 内容未形成有效变化时沿用现有去重规则，不制造新版本，不覆盖旧版本的作者和时间；无效草稿可保存但不可归档。

服务端拒绝客户端在业务写请求中指定或修改作者和时间。草稿保存、归档、作者记录和版本序号分配在事务中完成，自动与手动归档竞争时不会重复分配版本。

### 页面展示

版本列表卡片及版本详情均显示两行：

```text
最后编辑：alice · 2026-09-21 14:30:12（UTC+08:00）
提交：bob · 2026-09-21 14:32:08（UTC+08:00） · 手动提交
```

自动归档第二行显示“自动归档（关联用户：alice）”及提交时间。版本比较的左右两侧保留版本号，并显示各自编辑与提交信息。当前草稿在详情中显示最后编辑者和时间。

## 6. 服务边界与并发

- 认证模块：登录、退出、当前会话、本人改密；用户管理模块：账号列表、创建、启停、角色和密码管理。
- 业务模块：配置查询与详情、草稿保存、配置元数据、复制、配置归档和删除、版本查询与提交、版本恢复与清理、备份导入导出及共享设置。
- 服务端存储层负责账号、会话、工作空间业务数据、版本序号及作者元数据的事务持久化。浏览器不得上传任意完整状态替换服务端数据，也不得提交可执行修改函数。
- 对现有 `src/core.js` 的格式校验、内容摘要和差异逻辑进行复用；`src/store.js` 的业务操作抽离为接受可信操作者和服务端时钟的函数，持久化与业务规则分开。
- 前端通过 API 仓库适配层获取数据和执行命令，更新 `src/app.js` 的保存、归档、恢复和备份流程；加入登录、改密、用户管理及当前账号显示。
- 编辑和提交携带预期配置修订号，服务端事务内校验，不一致返回 409 并保留本机未提交文本；提示重新载入并人工处理冲突，不静默覆盖他人修改。
- 网络中断不切换到无鉴权写入模式；提示保存失败，保留当前内存编辑。会话失效后停止自动请求、清除已展示的共享数据并回到登录页；尚未保存内容按当前会话暂存于内存供重新登录同一账号后恢复，退出或切换账号时清除。
- 同一 SQLite 数据文件只由一个业务服务实例使用。重启不丢账号、已保存草稿和版本，自动归档调度重新扫描持久化的待归档草稿。

## 7. 旧数据与备份兼容

现有 IndexedDB 不自动上传。保留现有离线工具作为旧数据导出入口；在线版与离线版明确区分，离线工具不承诺角色控制，也不会直接访问在线数据。由 admin 或 operate 使用在线备份导入迁移配置和历史。

备份格式升级并保持读取旧版格式的能力。旧版本保留原始 `createdAt` 作为历史归档时间，用户名和编辑时间缺失时显示“未记录”；不将导入者冒充旧版本作者。

备份内携带的作者、用户名和时间属于外部历史声明，必须标记为“导入历史，身份未验证”，即使用户名与本地用户相同也不建立可信身份关联。导入者与导入时间由服务端单独记录。导入草稿在本机用户重新保存前不参与自动归档，防止伪造作者或将导入动作误记为原始编辑。

普通导入导出仅包含业务数据及历史署名，不包含账号、密码哈希、会话或权限设置。迁移不修改原浏览器数据库，同名冲突继续使用跳过或导入副本规则。

## 8. 验收标准

1. 首次部署能够初始化管理员、登录、强制改初始密码、退出；未知账号、错误密码、禁用账号不能访问受保护数据。
2. admin 可以创建并启停三类账号、分配权限；operate 和 readonly 即使直接调用用户管理 API 也得到 403；最后一个管理员受到事务保护。
3. readonly 可查询配置和版本差异，所有业务写入及导出接口被拒绝；只读页面停留、切换、查看草稿不会触发写入。
4. operate 可完成新增、编辑、草稿保存、归档、恢复、清理和备份流程；服务端校验输入、权限和版本关联。
5. 覆盖 A 编辑 B 提交、自动归档、历史恢复、无变化提交、无效草稿、作者禁用和降权场景，准确显示用户名及独立时间。
6. 客户端伪造作者或时间不能生效，旧记录和导入历史不会被错误归属于当前用户。
7. 两个用户并发保存或自动／手动同时归档时，修订冲突明确报错，版本号、作者和内容保持一致。
8. 改密、重置密码、角色变更、禁用、退出后旧会话失效；刷新、重新登录或切换账号不会显示前一个会话的缓存数据。
9. 服务重启后数据和署名仍存在，旧版备份能够迁移，配置备份不泄露账号与会话数据。
10. 运行现有转换、证书、存储回归测试；补充认证与权限 API 集成测试、版本署名及并发测试，并通过真实浏览器验证三类角色的完整路径。
