## 1. 目标与定位

建设一个在浏览器中使用的 HTML 工具集合，集中处理日常 Kubernetes 环境变量转换、JSON 整理、证书信息查看以及配置保存与追溯。

主要使用者为开发、测试和运维人员。典型使用过程为：粘贴配置 → 检查与转换 → 保存到项目和环境 → 后续修改 → 查看差异 → 导出或恢复历史版本。

产品保留离线工具，并分阶段建设受控访问的在线工具。两种形态共用转换与证书解析规则；身份、存储和网络边界分别定义。离线版在本机浏览器处理输入，依赖随工具分发；在线版增加服务端认证和账号管理，转换及证书解析仍在浏览器执行。

成功标准：用户能够在不静默丢失值、引用或顺序语义的前提下转换配置；明确区分草稿保存与版本快照；安全预览差异并恢复历史；通过备份迁移个人数据。在线访问控制阶段还必须做到账号可控、权限可验证、账号切换不串用工作空间。

### 1.1 用户与使用场景

| 角色 | 主要任务 | 成功结果 |
| --- | --- | --- |
| 开发、测试、运维人员 | 临时转换配置、查看公开证书 | 无需保存即可获得可复制、下载且与当前输入一致的结果 |
| 配置维护者（业务身份，不是独立权限角色） | 按项目与环境维护配置，比较和恢复版本 | 草稿可恢复、历史可追溯、数据可备份 |
| 在线普通用户 | 使用工具及自己的本地工作空间 | 仅启用的白名单账号可登录，无法进入账号管理功能 |
| 在线管理员 | 单个／批量创建普通用户，启停账号、重置凭据、查看审计 | 所有管理操作由服务端授权并留下可追溯结果 |
| 部署维护者 | 初始化管理员、部署、备份及恢复服务 | 有独立于网页普通用户操作的部署和恢复步骤 |

### 1.2 术语与非目标

| 术语 | 定义 |
| --- | --- |
| 临时处理 | 输入仅存内存，不自动进入配置库 |
| 配置集 | 项目和环境下的一份独立 env 或 JSON 配置，拥有稳定 ID |
| 草稿 | 最近编辑状态，可包含非法输入；不等于可恢复的正式版本 |
| 保存版本／版本快照 | 对校验通过的配置创建不可变历史记录 |
| 归档配置集 | 隐藏配置集且保留历史；不等于创建快照或删除 |
| 白名单 | 由管理员创建且启用的账号集合，不另设一份与账号状态可能不一致的名单 |
| 共享提交 | 未来向服务端共享配置显式发布变更；本地自动快照不触发共享提交 |

核心工具和在线访问控制阶段不包含集群连接、Secret 实值读取、配置下发、后台目录监控、Git 同步、多人协作、证书签发与续期、证书吊销和信任链验证。“自动管理”限定为工具内的个人配置管理。服务端个人数据与团队协作单独规划，不因增加登录自动纳入交付。

## 2. 产品形态、交付阶段与需求索引

### 2.1 产品形态

| 维度 | 离线版 | 在线访问控制版 |
| --- | --- | --- |
| 交付 | 独立 HTML，依赖随包分发；源码可拆分 | 虚拟机上的前端、认证后端与账号数据库 |
| 访问 | 无账号、无登录 | 服务端登录、会话、角色和启用状态校验；不开放自助注册 |
| 工具处理 | 浏览器本地转换与证书解析 | 同样在浏览器处理，不上传配置与证书正文 |
| 配置数据 | 当前浏览器来源下的本地工作空间 | 按部署实例及账号隔离的个人本地工作空间 |
| 服务端数据 | 无业务后端 | 账号、角色、会话、账号操作审计；不包含个人配置正文 |
| 网络 | 加载完成后的核心操作无网络依赖 | 登录、会话与账号管理访问同源后端；不承诺断网后继续受控访问 |
| 数据迁移 | 主动导出／导入备份 | 本阶段仍由个人备份迁移；登录不提供跨设备配置同步 |

## 3. 页面结构与交互

### 3.1 核心工具工作区

顶部显示工具名称、当前模块、主题切换和本地数据状态；左侧为模块导航，右侧为工作区。采用中文界面，可参考现有工具的紧凑布局和深色主题。

```text
┌─────────────────────────────────────────────────────────────┐
│ 运维工具箱                 本地数据状态           主题 / 设置 │
├────────────┬────────────────────────────────────────────────┤
│ env / JSON │ 输入格式 → 输出格式    自动排序    示例 / 清空   │
│ 证书解析   │ ┌──────────────────┐ ┌────────────────────────┐ │
│ 配置管理   │ │ 输入编辑区       │ │ 输出预览区             │ │
│ 版本归档   │ │                  │ │                        │ │
│ 数据备份   │ └──────────────────┘ └────────────────────────┘ │
│            │ 校验结果 / 项数 / 排序状态                      │
│            │ 转换    复制结果    下载    保存到配置集          │
└────────────┴────────────────────────────────────────────────┘
```

- 转换页：左右输入输出；宽度不足时上下排列。输入格式可自动识别，也可手动指定；识别结果有歧义时显示格式选择，不猜测修改内容。
- 证书页：输入或拖入文件，右侧展示字段卡片；多证书 PEM 按原输入顺序显示列表，不自行断言链关系。
- 配置页：项目 / 环境筛选、配置列表、编辑区、版本入口；选中配置后显示名称、类型、标签和保存状态。
- 版本页：限定配置集查看版本时间线，可选两个版本比较，也可与当前草稿比较。
- 备份页：导出范围选择、完整备份 / 脱敏分享选择、导入预览和冲突处理。
- 空状态提供可直接加载的示例；错误状态标注行列或字段路径；成功和警告同时用文字表达，不能只依赖颜色。
- 输入变化后旧输出标记为“待重新转换”，在成功生成新结果前禁用复制与下载，避免导出过期结果。

### 3.2 关键用户流程

| 场景 | 主流程 | 异常处理 |
| --- | --- | --- |
| 临时转换 | 输入 → 校验与预览 → 转换 → 复制／下载 | 格式不明确由用户选择；校验失败不替换为成功结果，不导出过期结果 |
| 纳管配置 | 转换成功 → 选择项目／环境／配置名 → 确认新建或更新 → 保存草稿及有效版本 | 重名、类型不符或写入失败时保留输入并提示 |
| 恢复历史 | 选择配置及版本 → 预览差异 → 保护未归档草稿 → 确认恢复 → 创建新版本 | 草稿保护或事务失败时停止，原历史不变 |
| 数据迁移 | 导出完整备份 → 另一工作空间导入 → 预览冲突 → 选择副本或跳过 → 确认 | 校验失败不写入；不能把脱敏分享当作恢复文件 |
| 在线普通用户 | 登录 → 必要时首次改密 → 进入个人工作空间 → 使用工具 → 退出 | 登录失败、禁用或会话过期进入明确错误／重新登录状态 |
| 在线管理员 | 管理员登录 → 用户列表 → 单个创建或批量预览与确认 → 交付临时凭据 → 查询结果与审计 | 普通用户直接访问管理地址仍被服务端拒绝；失败批次显示原因 |

在线顶部增加当前账号、角色及退出入口，明确“配置保存在此浏览器，未同步到服务器”。管理员可切换工具工作区与账号管理页；菜单是否可见仅用于交互，权限规则见第 9 节。

## 4. env / JSON 转换规则

### 4.1 输入输出格式

| 格式 | 示例或约束 | 首版支持 |
| --- | --- | --- |
| Kubernetes env YAML 数组 | `- name: APP_NAME` / `value: api` | 输入、输出 |
| 带 `env:` 的 YAML 片段 | 顶层只包含 `env` 字段 | 输入、输出 |
| Kubernetes env JSON 数组 | `[{"name":"APP_NAME","value":"api"}]` | 输入、输出 |
| JSON 键值对象 | `{"APP_NAME":"api","PORT":"8080"}` | 输入、输出 |
| 普通 JSON | 任意标准 JSON 值 | 仅格式化和排序；转 env 必须是顶层对象 |
| 完整 Deployment / Pod YAML | 含资源元数据、多个容器等 | P1；首版提示先提取 env |
| `.env` 文本 | `APP_NAME=api` | P1 |

标准 JSON 不接受注释、尾逗号、NaN 和 Infinity。JSON/YAML 中的重复键必须在解析阶段报告，不得由解析器静默覆盖。首版 YAML 接受普通映射、序列、标量和多行字符串；锚点、别名、自定义标签、合并键及多文档输入返回明确的不支持提示。

### 4.2 值与类型

1. env 的文字值使用字符串。`"001"`、`"false"`、空字符串和前后空白均原样保留。
2. JSON 键值对象默认仅接受字符串值。数字和布尔值可通过显式“将基本类型转为字符串”选项转换，并预览结果；不自动推断字符串的数字或布尔类型。
3. `null`、对象和数组不能直接转为 env 文字值，首版报错；用户可自行改为 JSON 字符串。避免产生 `"[object Object]"` 等无意义值。
4. 含 YAML 数字或布尔值的 env 输入同样要求显式字符串转换。解析、预览和转换不得静默舍入超出可安全表示范围的数字，应保留原数字文本或拒绝处理。
5. env 项仅有 `name`、未提供 `value` / `valueFrom` 时，在内部视为空字符串；界面提示补全。首版要求 `value` 与 `valueFrom` 二选一，即使某些 API 情况允许空值共存，也不输出歧义结构。
6. 单引号、双引号、反斜杠、换行、中文、emoji、冒号及 `#` 必须通过格式对应的序列化器转义，保证回转后字符串内容不变。YAML 注释、缩进和引号风格不保证保留；原始输入在草稿和版本中单独保存。
7. 同一 env 列表重名时阻止转换和归档，定位所有重复项；不得默认“后者覆盖前者”。空名称报错。
8. 名称校验区分“通用兼容提示”和硬错误。首版以 `[A-Za-z_][A-Za-z0-9_]*` 提示跨环境兼容性，但不把它宣称为所有 Kubernetes 版本的唯一合法规则；目标集群版本在开发前确认。

### 4.3 `valueFrom` 与无损模式

`valueFrom` 中的 `secretKeyRef`、`configMapKeyRef`、`fieldRef` 和 `resourceFieldRef` 保留完整引用结构；每项引用来源必须唯一，并校验对应必需字段。本地工具不解析引用到的真实值。env 的字段与引用定义以 Kubernetes API 文档为准。 [Pod API](https://kubernetes.io/docs/reference/kubernetes-api/core/pod-v1/)

```yaml
env:
  - name: APP_NAME
    value: "api"
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: database-secret
        key: password
```

该输入可转换为保持引用结构的 JSON 数组：

```json
[
  { "name": "APP_NAME", "value": "api" },
  {
    "name": "DB_PASSWORD",
    "valueFrom": {
      "secretKeyRef": { "name": "database-secret", "key": "password" }
    }
  }
]
```

含 `valueFrom` 时，转换为平面 JSON 键值对象必须阻止，并提供切换到结构化数组模式的按钮；不得将引用变成空字符串、占位符或静默删除。未知 env 字段保留在原始草稿中，阻止首版转换，避免声称无损却丢失字段。无损模式指已支持字段的语义保留，不指源文件字节一致。

### 4.4 自动排序

| 对象 | 默认行为 | 规则 |
| --- | --- | --- |
| JSON 对象 | 自动按键升序 | 递归排序对象，所有数组保留原顺序 |
| 无变量展开的 env | 自动按 `name` 升序 | 移动整个 env 项，不改变值或引用结构 |
| 含变量展开的 env | 保留原序 | 提示“存在变量引用，已跳过自动排序” |
| 用户关闭自动排序 | 保持输入顺序 | 仅进行格式转换和缩进整理 |

排序采用区分大小写的 Unicode 码点字典序，不依赖操作系统语言；可选择降序。不采用自然数排序，因此 `KEY_10` 排在 `KEY_2` 前。数字形式 JSON 键也按同一规则输出，序列化实现不能依赖 JavaScript 对整数键的默认枚举次序。

Kubernetes 的 `$(NAME)` 展开依赖 env 列表中变量定义的先后；`$$(NAME)` 为转义形式。首版检测到任何未转义变量展开时保留整个 env 列表原序，包括看起来可通过依赖排序修正的情况，避免改变原有未展开引用的含义。检测实现须覆盖连续 `$`，不以简单子串匹配代替解析。 [Kubernetes 变量依赖规则](https://kubernetes.io/docs/tasks/inject-data-application/define-interdependent-environment-variables/)

将含展开表达式的 env 转为平面 JSON 会丢失可靠的执行顺序语义，因此首版也阻止该操作，建议使用结构化数组；从 JSON 对象转 env 时，若值包含未转义展开表达式，同样要求用户改用明确有序的 env 数组。普通 JSON 格式化可保留这些字符串，但不宣称其排序结果可直接作为 Kubernetes 执行顺序。

### 4.5 常规示例

输入 JSON：

```json
{"PORT":"8080","APP_NAME":"demo","DEBUG":"false","EMPTY":""}
```

默认输出：

```yaml
env:
  - name: APP_NAME
    value: "demo"
  - name: DEBUG
    value: "false"
  - name: EMPTY
    value: ""
  - name: PORT
    value: "8080"
```

回转为 JSON 后四个值均为字符串；内容相同，仅对象键的显示顺序改变。

## 5. 证书基本信息解析

### 5.1 输入与展示

支持粘贴单张或多张 PEM 证书，上传 `.pem`、`.crt`、`.cer` 和 `.der` 文件；以实际内容识别格式，扩展名仅作为提示。DER 首版按单张证书处理。证书字段与文本封装分别参考 [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280) 和 [RFC 7468](https://www.rfc-editor.org/rfc/rfc7468)。

| 分组 | 展示字段 |
| --- | --- |
| 基本信息 | X.509 版本、序列号（十六进制文本）、Subject、Issuer |
| 主体信息 | CN、组织、组织单位，以及完整 DN；保留重复属性 |
| 有效期 | Not Before、Not After、剩余时间、有效期状态 |
| 域名与用途 | SAN 的 DNS / IP 等条目、Key Usage、Extended Key Usage、Basic Constraints（存在时） |
| 算法 | 签名算法、公钥算法、RSA 位数或 EC 曲线等可识别参数 |
| 指纹 | 原始 DER 字节的 SHA-256，十六进制显示 |

缺失的可选字段显示“未提供”；未知算法或扩展显示 OID，不使其他字段解析失败。提供单字段复制、信息 JSON 下载、输入清空。证书输入首版不自动加入配置仓库或浏览器历史。

### 5.2 状态与错误

- 以本机时间计算有效期：`now < notBefore` 为“尚未生效”，`now > notAfter` 为“已过期”，其余为“有效期内”。
- 有效期内且剩余时间不超过 30 × 24 小时显示“即将到期”；阈值可设置。比较精确时间戳，剩余天数仅作展示，边界值不能因取整误判。
- 同时显示 UTC 时间和本地时区时间，明确此处只判断时间范围，未验证信任链、签名、用途适配或吊销状态。
- 损坏的 PEM、非法 Base64、截断 DER、非证书 ASN.1 返回可理解的错误；多张 PEM 中某张错误时定位该项，其余可单独查看，整体标记“部分解析失败”。
- 私钥、CSR、PFX / P12 不在首版支持范围；发现私钥块时停止处理该输入，不将其写入持久化存储。
- PEM 去除封装后与等价 DER 应产生相同 SHA-256 指纹。

## 6. 配置项自动管理

### 6.1 组织模型

层级为“项目 → 环境 → 配置集 → 配置项”。同一个环境下可以存在多份配置集，例如 `订单服务 / test / api-env` 和 `订单服务 / test / worker-env`。

配置集包含名称、类型（`k8s-env` 或 `json`）、描述、标签、创建时间、修改时间及最新版本。项目和环境允许自定义，默认示例环境为 `dev`、`test`、`prod`；同项目同环境下配置集名称唯一。

env 配置项以名称和完整值来源管理；普通 JSON 采用结构化编辑或文本编辑，不强制拆成平面键值表。重命名配置集不改变其标识，也不丢失历史。

### 6.2 操作与自动行为

| 操作 | 行为 |
| --- | --- |
| 从转换页保存 | 选择项目、环境和配置名，预览后新建配置集或更新已选配置集 |
| 编辑配置 | 修改值、增加或移除配置项；支持文本视图与 env 表格视图 |
| 搜索 | 按配置名、键名、描述及标签搜索；默认不索引敏感值 |
| 复制到另一环境 | 创建独立配置集，显示来源；以后修改互不影响 |
| 归档配置集 | 从默认列表隐藏，版本仍可查看；恢复归档后可继续编辑 |
| 删除配置集 | 明确显示将一并删除的版本数量，由用户确认后删除 |
| 自动保存草稿 | 停止输入 800 ms 后写入当前配置集草稿，内容不合法也可保存草稿 |
| 恢复草稿 | 重开页面后提示恢复最近已保存草稿，保留原始输入和校验结果 |

临时转换输入默认仅存内存；选择“保存到配置集”后才进入自动保存和版本管理。界面分别显示“草稿已保存”和“已归档为 vN”，不能以单个“已保存”混淆二者。

密码、Token 等字段可按名称建议标记为敏感，用户可手动修正；列表、比较和分享预览默认遮罩，查看和复制原值由用户主动操作。遮罩不等于存储加密；首版完整配置存于当前浏览器，支持只在内存中处理、不保存的临时用法。

## 7. 版本归档与恢复

### 7.1 版本生成

每个配置集维护独立递增版本号 `v1、v2、v3…`。版本内容创建后不可覆盖；修改配置继续生成下一版本。

- 首次保存校验通过的配置时生成 v1。
- 自动归档默认开启，可在设置中关闭。有效内容相对最新版本发生变化后，若连续 2 秒无编辑且距上一次归档至少 60 秒，则生成自动版本；尚未满足时间条件时继续等待，不能只依赖下一次按键触发。
- 点击“保存版本”立即校验并创建快照，可填写备注；无有效变化时提示“内容未变化”，不生成重复版本。
- 格式不合法的内容只保存草稿，不进入可恢复的正式版本。
- 仅缩进、换行风格或 JSON 对象键顺序变化，不触发新版本；env 项顺序、JSON 数组顺序、值类型、字符串内容、配置项增删及引用来源变化均触发。
- 每个版本保存规范化内容、当时的原始输入、格式、时间、操作来源、备注和内容摘要。格式整理不生成版本时，最新格式仅保留在草稿中。

内容摘要基于确定性的规范化序列化：对象键排序，数组保持顺序，字符串内容与类型保留；env 按有序数组参与摘要。摘要包含配置类型和模型版本，不包含时间戳或备注。

### 7.2 差异比较

- env 以名称匹配，展示新增、删除、值修改、引用来源修改及顺序调整；从文字值改为 `valueFrom` 必须可见。
- JSON 按字段路径比较，保留数组的索引和顺序含义；提供文本差异作为补充。
- 标明左、右版本号与时间，以及是否包含未归档草稿。
- 敏感项显示“值已变化”而非默认暴露内容；脱敏结果不得用于实际回滚。

### 7.3 恢复语义

例如当前最新版本为 v5，选择恢复 v2，应创建内容等同 v2 的 v6，并记录 `restoredFromVersionId`，原 v3～v5 保留。目标与当前最新正式版本按 7.1 的内容摘要规则相同，提示无需恢复，不创建重复版本，也不覆盖可能不同的当前草稿。此处“无差异恢复不覆盖草稿”为本轮歧义补充，见 D-04；丢弃草稿不隐含在历史恢复操作中。

恢复前展示差异。如果存在未归档草稿，先将该草稿保存到独立恢复草稿记录；保存失败则停止恢复。数据库事务成功后才更新当前配置及 UI，不能显示已恢复却没有写入数据。

### 7.4 历史保留

首版不自动删除正式历史版本；允许按配置集选择清理范围并预览数量，最新版本不得删除。删除前可导出备份。版本清理后不复用版本号。配置归档是隐藏配置集，版本归档是创建快照，两项操作在界面采用不同名称。

## 8. 本地存储与备份

### 8.1 数据关系与存储约束

下表字段为技术设计建议，不是固定数据库表或 API 契约；验收必须保证其表达的关联完整性、稳定标识、历史不可变及并发保护。M2 还须满足第 9.4 节的工作空间归属约束。

| 实体 | 关键字段 |
| --- | --- |
| Project | `id, name, createdAt` |
| Environment | `id, projectId, name` |
| ConfigSet | `id, projectId, environmentId, name, type, description, tags, archivedAt, latestVersionId, nextVersionNumber, revision` |
| Draft | `configSetId, rawInput, inputFormat, options, validationState, baseVersionId, revision, updatedAt` |
| RecoveryDraft | `id, configSetId, rawInput, inputFormat, options, reason, createdAt` |
| ConfigVersion | `id, configSetId, versionNumber, modelVersion, rawInput, inputFormat, normalizedContent, contentHash, itemMetadata, source, note, createdAt, restoredFromVersionId` |
| Settings | `schemaVersion, theme, sortOptions, autoArchiveEnabled, expiryWarningDays` |

`itemMetadata` 保存敏感标记等配置项属性，JSON 项使用可转义的字段路径标识；env 项使用名称标识。时间统一保存 UTC ISO 8601，界面按本地时区展示。配置集 ID 为稳定标识，不使用名称或时间戳充当唯一主键。

配置和版本使用 IndexedDB；少量界面偏好可使用 localStorage。一次版本生成应在单个事务内完成版本写入、版本号递增和配置集指针更新。使用 `revision` 检测多标签页的并发编辑，冲突时提示重新加载或另存，禁止静默覆盖。

浏览器数据按来源隔离，也可能因用户清理或存储策略被删除，因此数据库不能代替外部备份。正常持久化使用固定的 localhost 地址或静态 HTTPS 地址；双击 HTML 的 `file://` 模式优先保证临时工具可用，持久化能力需检测，失败时明确进入临时模式。 [IndexedDB 使用说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)、[浏览器存储配额与清理](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

### 8.2 导出和导入

- 配置导出：下载当前 JSON 或 YAML 内容，文件名包含配置名、环境和版本；非法文件名字符统一替换。
- 完整备份：生成带 `schemaVersion`、工具版本、导出时间、项目、环境、配置集、版本、草稿、恢复草稿、敏感标记和设置的 JSON 包，可恢复选定范围内的全部内容。明确标示包含原始值。全量备份包含整个个人工作空间；单配置集备份携带该配置及其历史、草稿和恢复所必需的关联数据，不带其他配置的内容。恢复草稿和敏感标记的完整性补充见 D-04。
- 脱敏分享：按敏感标记替换值，标记 `redacted: true`；与完整备份分开操作，不允许作为完整恢复文件导入。
- 导入先校验包结构、大小、版本、唯一性、引用完整性及内容摘要，再展示项目数、配置数、版本数及冲突清单；未知高版本备份拒绝导入。
- 首版以“导入为副本”为默认策略，为项目、环境、配置、版本和恢复草稿生成新 ID，并重映射全部关联关系，包括最新版本、草稿基础版本和恢复来源；同名配置追加可见后缀。跳过冲突以配置集为单位，同时跳过其版本、草稿及恢复草稿，预览最终写入数量且不得产生悬空引用；此粒度补充见 D-04。首版不提供静默覆盖或自动历史合并。
- 导入正式写入使用事务；任何记录失败则整体回滚，现有配置保持完整。
- 存储不可用、配额不足或备份失败时，保留当前内存内容，显示失败原因并提供下载入口，不显示成功状态。

## 9. 在线访问控制与账号管理（M2）

本节将原在线版摘要补全为可评审要求。保留“不开放注册、管理员维护白名单、统一账号体系、服务端授权、个人本地数据隔离”的既有边界；账号规范、批处理事务、会话参数和退出时本地数据策略等新增建议列入第 13 节，不视为已获确认。

### 9.1 角色与权限

普通用户和管理员使用统一账号体系，分别提供 `/login` 和 `/admin/login` 入口。登录入口不授予权限，角色以服务端记录为准；管理员同时具有普通工具使用权。

| 操作 | 未登录访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 查看登录页、提交登录 | 允许 | 允许 | 允许 |
| 首次修改临时密码 | 仅持受限改密会话时允许 | 按账号状态要求 | 按账号状态要求 |
| 使用工具、访问自己的工作空间 | 拒绝 | 允许 | 允许 |
| 创建、查询、编辑普通用户资料 | 拒绝 | 拒绝 | 允许 |
| 批量创建普通用户、启停及重置账号 | 拒绝 | 拒绝 | 允许 |
| 查看账号操作审计 | 拒绝 | 拒绝 | 允许 |
| 查看其他用户的个人配置 | 拒绝 | 拒绝 | 不提供此能力 |
| 从个人配置备份创建账号或授予角色 | 拒绝 | 拒绝 | 拒绝 |

受保护工具入口、管理页面及业务接口必须经过服务端校验；隐藏按钮或前端路由跳转不能替代授权。初始管理员由部署流程建立，普通用户创建接口不得创建管理员；后续管理员生命周期另行评审。

### 9.2 登录、会话与凭据

1. 只有存在且启用的账号可以完成登录。不存在、禁用或密码错误使用不泄露账号存在性的失败提示；登录失败不得获得有效会话。
2. 首次使用临时密码、管理员重置密码后，用户先进入强制改密流程；改密完成前只允许必要的改密、会话检查和退出操作。
3. 服务端保存不可逆密码校验信息，不保存或返回可还原的正式密码。登录与改密全程使用 HTTPS；服务端校验输入并限制连续失败尝试。
4. 会话凭据由服务端通过具备 HttpOnly、Secure 及适当 SameSite 属性的 Cookie 管理；不得写入 localStorage、IndexedDB、URL 或普通日志。改变账号状态等写操作必须防止跨站请求伪造。
5. 用户退出后当前会话失效；禁用账号或重置密码后该账号已有会话全部撤销。服务端在后续受保护请求中检查账号状态，重新启用不得复活已撤销会话。
6. 会话必须有空闲与绝对有效期；具体值见 D-07。过期后提示重新登录，不在未认证状态下继续执行后台请求。已发送但未得到结果的管理操作显示“结果待核实”，重新查询后才能重试，避免重复创建。
7. 账号管理不提供自助注册、邮件找回密码、第三方登录、MFA 或管理员在页面中查看用户原密码；这些功能不属于本阶段承诺。

### 9.3 普通用户管理与批量创建

**单个创建与维护**：管理员填写登录名及显示名；登录名规则及唯一性按 D-06 确认，建议创建后不可更改。可编辑显示名、查询账号及按启用状态筛选。停用不删除账号标识和审计记录；账号删除及身份转让不在本阶段提供。

创建成功时生成临时凭据，并标记首次登录必须改密。管理员通过受控方式交付给用户；临时明文凭据只在本次结果中展示或下载，不写入审计、浏览器持久化存储或可再次查询的普通列表。交付失败时通过重置产生新凭据，不找回旧明文。

**批量创建建议流程**：下载模板 → 上传 UTF-8 CSV → 逐行校验 → 展示预览 → 管理员确认 → 服务端再次校验并创建 → 展示结果。

| 环节 | 可验收行为 |
| --- | --- |
| 模板 | 字段为登录名、显示名；不接受角色、管理员标志或自带密码列；行数和文件大小上限在 D-06 确认 |
| 预校验 | 检查必填项、字段长度与格式、文件内重复及数据库已存在账号；明确行号和原因，不静默覆盖 |
| 预览 | 显示总行数、有效行数及错误行；建议有错误时整批阻止提交，修正后重新预览 |
| 确认 | 预览本身不创建账号；确认时重新检查权限、启用状态及唯一性，防止预览后数据变化导致冲突 |
| 写入 | 建议单次批次全成或全败；任何创建失败整体回滚，不把失败批次描述为成功 |
| 重复提交 | 同一批次重复点击或请求重试不重复创建账号；通过批次标识查询最终结果 |
| 结果 | 成功显示创建数量和账号清单；失败显示原因且已有账号不受影响；凭据文件只允许当前授权管理员在本次交付流程取得 |

批量结果文件应按数据文本安全导出，避免显示名等用户输入在表格软件中作为公式执行。批量文件格式、容量及全成全败策略均为本轮建议，见 D-06。

### 9.4 在线数据边界与审计

**数据归属**：M2 服务端仅保存账号、角色、启用状态、密码校验信息、会话和账号操作审计。env／JSON 配置、证书输入、个人草稿和历史仍在浏览器，不能因已登录而自动上传。管理员账号数据库备份与个人工具备份是两个独立交付物。

**工作空间隔离**：个人本地数据的范围键必须包含稳定部署实例标识及不可复用的账号 ID，不使用显示名或可变登录名作为身份。页面认证完成前不加载个人工作空间；从账号 A 切到 B 时不得展示、搜索、导出或续写 A 的数据。离线旧数据库不得自动归属第一个登录账号，迁移必须通过用户选择备份、预览并确认导入当前账号。

**失效与切换**：退出、切换账号或前端得知会话失效后，立即隐藏个人视图，清除当前内存输入、结果和凭据展示，停止旧账号的自动保存与快照定时器，关闭旧工作空间。待完成的旧异步回调不得把 A 的内容写入 B。多标签页同步退出与切换信号；跨设备禁用由服务端请求校验保证，前端轮询周期见 D-07。

**本地持久化限制**：建议保留按账号隔离的数据库供同账号下次登录恢复，提供单独的“清除此设备本账号数据”操作，并明确提示不可恢复及备份入口。浏览器中的账号隔离是应用工作空间边界，不构成对同一浏览器配置文件拥有者的加密保密保证。若场景要求共享设备上退出后不可读取数据，必须先按 D-08 改为清除、加密或服务端存储策略再交付；M2 不宣称能远程撤回已下载的文件或离线副本。

**审计**：记录登录结果、退出、创建账号、批量创建、启停、重置凭据及管理员初始化。字段至少包含操作时间、操作者、目标账号或批次、动作、结果及关联请求标识；不得包含密码、会话凭据、配置正文或证书输入。账号变更成功必须有对应审计记录；普通用户不能读取或修改审计，管理员页面只读。保留期限见 D-09。

### 9.5 部署、初始化与恢复

- 在线版部署前端、同源认证后端及账号数据库，外部入口提供 HTTPS。未认证请求不能绕过认证层直接取得受保护工具页面或访问后台接口；允许公开的登录资源必须有明确范围。
- 首个管理员通过部署维护者控制的一次性初始化流程建立，不提供公开注册管理员的网页入口，不附带通用默认密码。初始化完成后该入口关闭或拒绝重复执行。
- 部署手册需说明域名及证书、服务启动停止、配置注入、数据目录、备份与恢复、升级失败恢复步骤；不得把账号秘密写入前端资源或仓库。
- 账号数据库备份必须包括恢复账号、角色、状态及审计所需的数据，并有访问限制。恢复后强制现有会话重新登录；在隔离环境演练恢复，确认禁用状态与权限保留。
- 个人配置备份不能创建账号、修改角色、启用账号或恢复管理员会话。账号数据库备份不能声称包含浏览器中的个人配置。
- 登录或后端不可用时，明确提示无法验证身份，禁止自动降级为匿名在线工具。离线版独立分发；保存过的离线副本不受在线白名单撤销控制。
